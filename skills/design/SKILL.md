# Design

## Use When

Use for websites, dashboards, landing pages, interface redesigns, or frontend visual direction.

## Procedure

1. Read the existing stack, design system, content, brand, and user goals.
2. Present distinct visual directions before committing to one.
3. Define typography, color, spacing, shape, interaction, and responsive tokens.
4. Build the selected direction within the existing architecture.
5. Check desktop and mobile layouts, contrast, semantics, keyboard access, focus, reduced motion, loading, empty, error, and success states.

## Verification

Report the selected direction, token decisions, changed files, responsive checks, and accessibility checks.

## Boundaries

Preserve an existing design system when one exists. Do not invent a stack or brand, copy a reference wholesale, or accept inaccessible defaults.
