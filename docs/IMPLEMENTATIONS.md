# Implementations

## Language Model Clients

One implementation speaks the standard chat-completions protocol over standard-library networking facilities. It supports both buffered and streaming modes, accumulates tool-call deltas by index with handling for name and argument fragments that may arrive separately or as already parsed structures, handles server-sent event framing including the terminating sentinel and usage objects, and retries with backoff. Consecutive data lines are buffered into one event and parsed at the blank-line separator, with a fallback to per-line parsing when a stream sends each chunk without separators, so a JSON payload split across continuation lines is not mistaken for malformed noise.

It performs per-field downgrades when a server rejects optional parameters such as usage inclusion, reasoning effort, sampling temperature, or token-limit naming, switching the token field name where needed and remembering the choice for subsequent turns, with word-boundary checks to avoid shedding a field a server did not actually blame. It also provides a fallback that translates a chat payload to a responses shape when the chat endpoint returns a bad-request, not-found, or server error, chaining the original error when the fallback also fails. Credentials are resolved from the configured lookup and included as a bearer token when present; loopback hosts are treated as keyless so a local inference server never needs an invented credential. Headers include an identifier. A one-time warning is emitted when a credential would cross plain HTTP.

Response size, streamed content, tool-argument accumulation, single server-sent events, and the whole streamed response are all capped so a garbage or hostile stream cannot grow memory without bound. The parser limits both consecutive and total malformed streaming fragments. A mid-stream drop after any content was emitted fails the turn instead of retrying, to avoid duplicate output in the user interface; a stream that ends without the sentinel sentinel is treated as transient when no content was emitted. Reply content is normalized to plain text: list-of-parts shapes are joined, and foreign shapes are rejected rather than leaked into the conversation.

A second implementation replays a fixed script of responses for offline testing and raises when the script is exhausted. A helper builds single-tool-call responses with unique identifiers, and a loader turns a scripted-conversation document into replayable responses. A streaming variant emits a reply word-by-word through the callback so the render path is exercised.

## Sandboxes

The host directory sandbox executes directly in a workspace directory on the host, creating the directory if needed and using a temporary directory when none is supplied. It validates repository addresses and commit identifiers, blocks traversal including encoded traversal and home-directory and environment-variable expansion in commands including shell expansions, and runs commands via the host process facility with polling to support abort and timeout and with caps on output size. Each child runs in its own process group or session so a timeout or abort can kill the whole tree, not just the direct child; otherwise survivors keep the output pipes open and the reader threads never see end-of-file. Output is read incrementally by daemon threads into capped buffers so a chatty command stays memory-bounded. When both pipes reach end-of-file the child is confirmed to have exited, and a survivor is tree-killed so no process is orphaned.

Path resolution rejects escapes via symlink resolution at read, write, and directory-creation time, checks each component of newly created parent chains for symbolic links, re-resolves the full path after directory creation, rejects symbolic-link targets, and stages writes through a uniquely named temporary file before the atomic replace, so no predictable staging path exists for a concurrent process to hijack. The fallback direct-write path re-runs the full confinement check before writing. Reads are capped and truncated with a marker, and writes are rejected when content would exceed the allowed size. The child environment is filtered to strip credential-shaped variables. Repository-address, commit, and screening helpers are shared with the container sandbox from single modules.

The container-based sandbox manages a disposable container via the container runtime interface, creating the container detached and hardened, with a validated image name, memory limit, workdir, processor limit, process limit, dropped capabilities, no new privileges, and an unprivileged user. Input validation rejects malformed image names, out-of-range memory limits, and non-normalized workdirs at construction time. A setup failure after the container starts removes the container before surfacing the error so the resource reservation is not leaked. Commands execute via the runtime with polling for abort and timeout. Output is pumped incrementally under a byte cap so chatty in-container commands stay memory-bounded. Cleanup removes the container, and execution respects abort signals. Because the network setting is fixed for the container's lifetime, it is named for what it actually controls.

## Tools

File tools provide reading with windowed display, byte and per-line caps, and header notes for truncated views whose resume offset counts only the lines actually shown after a byte-budget cut. Bulk reads report how many files matched on disk versus how many were read, count cap-skipped files against their own header, and treat per-file notes such as empty files as legitimate results rather than failures. Repeated reads of an unchanged window are served from a bounded in-memory cache that returns the cached result directly and evicts the least recently used entry when over capacity. A genuine file whose name contains a glob metacharacter or a comma wins over pattern or list reading. Missing files offer did-you-mean suggestions from a bounded walk. Writing creates parent directories with post-creation validation and ledger recording. Editing enforces read-before-edit and stale-content checks and rejects edits when the file was truncated due to size, when only a partial view was seen, when the file contains invalid UTF-8, or when the anchor occurs more than once. Directory listing validates against shell metacharacters and uses safe quoting when the sandbox has no direct file view.

The ledger enforces the read-before-edit invariant via content hashing with normalized path keys that fold case only where the platform's filesystem is case-insensitive. File tools reject paths containing invalid characters, device names, trailing dots or spaces, or alternate data streams, and block device and process-pseudo files, sampling multiple windows for binary detection.

Command tools execute a shell command and format the result as exit status, timeout flag, and truncated output with middle-out handling, untrusted fencing, honest exit codes, and full log capture. Background execution requires explicit opt-in, is refused by any sandbox without a direct host root, spawns the task in its own process group so timeout and abort kill the whole tree through a shared tree-kill helper, screens the command before spawning, and writes logs to workspace-private or per-process private locations with restricted permissions. The registry of background tasks is bounded, pruned by age after completion, and accompanied by a bounded registry of spilled full-output log files. Completion of a workspace task prunes older finished task logs. Kill-by-task-identifier is registry-local; kill-by-process-id and kill-by-port are restricted to the host sandbox and to processes the registry recorded, so a container cannot use them as an isolation escape. Difference and reset tools display version-control differences and discard changes with timeout handling.

Search tools walk the workspace without descending into ignored directories, honor the ignore matcher for both directories and files, filter symlinked directories and files that point outside the workspace, skip files above the size limit and files with non-text extensions, and return matching lines or file names with limits on result count, scanned-file count, and line length, noting when ceilings are reached. Negated ignore patterns are ignored by design. An alternate shell-based path serves sandboxes without a direct file view, quoting the query literally and disabling option parsing.

The extraction tool renders a single structured file to bounded plain text: markup to visible text with non-visible elements dropped, JSON pretty-printed, XML indented, CSV rows joined, markdown normalized to prose, and ini-like configuration reduced to settings. Decoding tries a byte-order-mark-aware pass, then a UTF-8 pass, then a never-failing single-byte fallback. Files above the byte cap are refused with a pointer to windowed reads; unrenderable extensions are reported as a note rather than parsed; malformed structured content falls back to a short raw snippet; and the shell-fallback path supports only literal paths with safe quoting.

The tree-query tool matches literal paths and globs against the walk with the same ignore, symlink, and ceiling rules, and adds a small brace-shaped syntax: list a directory's children with directory markers, match a one-level glob, match a recursive glob, or descend through literal directory segments, with the resolved target re-validated against the workspace root at every step so traversal and escaping symlinks are refused. Shell metacharacters are rejected at the pattern level.

Web fetching retrieves a URL, enforces scheme and size and decompression limits during and after inflation, decodes according to the declared character set with fallbacks, extracts visible text from markup while dropping non-visible elements and collapsing whitespace, screens private, loopback, link-local, reserved, and metadata hosts including alternative numeric encodings without resolving names, then resolves the host once at connect time and refuses private or unresolvable addresses, which makes that pinned connection the single authority for name resolution, validates each redirect target including rejecting non-http schemes, pins the connection to the address that was validated, and returns an error string rather than raising. Credentials in a URL are stripped from the displayed form and credential-named query parameters are redacted.

## Evaluators and Loggers

One evaluator runs a shell command and interprets a zero exit status without timeout as pass, with per-task override support and tail truncation. Its configured timeout is validated into the allowed range at construction so an out-of-range value surfaces as a configuration error rather than a wall of silent failures, and a non-string task-level command is rejected as a failed evaluation instead of raising inside execution. The evidence tail is redacted for known secret formats before it is returned. The other evaluator always reports a neutral result for interactive sessions without automated grading.

The structured logger appends one serialized record per line with a timestamp, event name, and payload, using both in-process and inter-process locks with verified stale handling: the holder's liveness is probed before a lock is broken, and any lock past a hard age ceiling is removed regardless so a wedged writer cannot block later records. It suppresses input and output errors, rotates the log aside at a bounded size, and counts records skipped under lock contention or lost to a failed write rather than losing them silently. It performs no redaction of its own; callers are responsible for the payloads they pass.

External tool interoperability is implemented in both directions over the newline-delimited JSON transport the protocol specifies, with no third-party dependency. The exposing side presents the same tool objects and the same workspace sandbox the agent loop uses, gates every invocation through the approval policy so a remote caller cannot reach what the local path would have refused, and reports a tool failure as an error-flagged result rather than a protocol fault. The consuming side launches each configured server as a child process, performs the handshake, lists the advertised tools, and wraps each in an ordinary local tool whose name is folded into the characters a function name may contain; the adapter ignores the local sandbox because the work happens in the server's own environment, and it registers itself as an external tool so the approval policy always requires explicit confirmation rather than classifying it as an unfamiliar but harmless name. A server that cannot start is reported and skipped, so one broken optional server does not prevent startup.

## Terminal Primitives and Theme

Shared terminal helpers provide visible string width that counts wide characters double and zero-width characters as none, with zero-width-joiner sequence awareness scoped to each measured string so no measurement is influenced by an unrelated one, console size detection with a standard-library fallback, raw and cbreak input modes where cbreak keeps interrupt signals delivered, safe writing that degrades unencodable characters without duplicating the written prefix, and UTF-8 output forcing with virtual-terminal enablement on the host console. Escape-sequence stripping treats an unterminated operating-system command as extending to the end of the string so it cannot corrupt width math, and recognizes colon-form color sequences. The theme module defines a single restrained palette of styled tokens used by every surface the console draws, with one identity accent, distinct tokens for semantic states, and diff text colors aliased to the semantic tones so a future split changes in one place.
