# Implementations

## Language-Model Clients

One client speaks the common chat-completions protocol over standard-library networking. It supports buffered and streaming modes, accumulates tool-call deltas by index with fragments that may arrive separately or already parsed, handles stream framing including the terminating sentinel and usage objects, and retries with backoff. Consecutive data lines are buffered into one event and parsed at the blank-line separator, with a per-line fallback for streams that omit separators so a payload split across continuation lines is not mistaken for noise.

It downgrades fields individually when a server rejects optional parameters such as usage inclusion, reasoning effort, sampling temperature, or token-limit naming, switching the token field name where needed and remembering the choice for later turns. Word-boundary checks avoid shedding a field the server did not actually blame. When the chat endpoint returns a bad-request, not-found, or server error, a fallback translates the payload to an alternate shape, chaining the original error when the fallback also fails. Credentials resolve from the configured lookup and are sent as a bearer token when present. Loopback hosts are treated as keyless so a local inference server needs no invented credential. Requests carry an identifier header, and a one-time warning is emitted when a credential would cross an unencrypted connection.

Response size, streamed content, tool-argument accumulation, single events, and the whole streamed response are capped so a hostile stream cannot grow memory without bound. The parser limits consecutive and total malformed fragments. A hard mid-stream drop after any content was emitted fails the turn instead of retrying, to avoid duplicate output in the interface. A read-timeout pause, typically a silent reasoning stretch outlasting the read timeout after partial output, is distinguished and treated as retryable so the loop nudges and raises the output budget before trying again. A stream that ends without the sentinel is transient when no content was emitted. Reply content is normalized to plain text, with list-of-parts shapes joined and foreign shapes rejected rather than leaked into the conversation.

A second client replays a fixed script of responses for offline testing and raises when the script is exhausted. A helper builds single-tool-call responses with unique identifiers, and a loader turns a scripted-conversation document into replayable responses. A streaming variant emits a reply word by word through the callback so the render path is exercised.

## Sandboxes

The host-directory sandbox executes directly in a workspace directory on the host, creating it if needed and using a temporary directory when none is supplied. It validates repository addresses and commit identifiers, blocks traversal including encoded traversal and home-directory and environment-variable expansion in commands, and runs commands through the host process facility with polling for abort and timeout and with output caps. Each child runs in its own process group or session so timeout or abort can kill the whole tree; otherwise survivors keep output pipes open and reader threads never see end of file. Output is read incrementally by daemon threads into capped buffers. When both pipes reach end of file the child is confirmed to have exited and a survivor is tree-killed so no process is orphaned.

Path resolution rejects escapes through symbolic-link resolution at read, write, and directory-creation time, checks each component of newly created parent chains for symbolic links, re-resolves the full path after directory creation, rejects symbolic-link targets, and stages writes through a uniquely named temporary file before the atomic replace. The fallback direct-write path re-runs the full confinement check. Reads are capped and truncated with a marker, and writes are rejected when content would exceed the allowed size. The child environment is filtered to strip credential-shaped variables. Address, commit, and screening helpers are shared with the container sandbox from single modules.

The container sandbox manages a disposable container through the host's container runtime interface, creating it detached and hardened with a validated image name, memory limit, working directory, processor limit, process limit, dropped capabilities, no new privileges, and an unprivileged user. Input validation rejects malformed image names, out-of-range memory limits, and non-normalized working directories at construction. A setup failure after the container starts removes the container before surfacing the error so the reservation is not leaked. Commands execute with polling for abort and timeout, and output is pumped incrementally under a byte cap. Cleanup removes the container and execution respects abort signals. Because the network setting is fixed for the container's lifetime, it is named for what it actually controls.

## Tools

File tools provide reading with a window, byte and per-line caps, and header notes for truncated views whose resume offset counts only the lines actually shown after a byte-budget cut. Bulk reads report how many files matched on disk versus how many were read, count skipped files against their own header, and treat per-file notes such as empty files as results rather than failures. Repeated reads of an unchanged window come from a bounded in-memory cache that evicts the least recently used entry when over capacity. A genuine file whose name contains a pattern metacharacter or a comma wins over pattern or list reading. Missing files offer suggestions from a bounded walk. Writing creates parent directories with post-creation validation and ledger recording. Editing enforces read-before-edit and stale-content checks and rejects edits when the file was truncated, when only a partial view was seen, when it contains invalid text encoding, or when the anchor occurs more than once. Directory listing validates shell metacharacters and uses safe quoting when the sandbox has no direct file view.

The ledger enforces read-before-edit through content hashing with normalized path keys that fold case only where the platform's filesystem is case-insensitive. File tools reject paths containing invalid characters, device names, trailing dots or spaces, or alternate streams, and block device and process-pseudo files, sampling multiple windows for binary detection.

Command tools execute a shell command and format the result with exit status, timeout flag, and truncated output with middle-out handling, untrusted fencing, honest exit codes, and full log capture. Background execution requires explicit opt-in, is refused by sandboxes without a direct host root, spawns in its own process group so timeout and abort kill the whole tree through a shared helper, screens the command before spawning, and writes logs to private locations with restricted permissions. The background registry is bounded, pruned by age after completion, and accompanied by a bounded registry of spilled output logs. Completion of a workspace task prunes older finished logs. Termination by task identifier is registry-local; termination by process or port is restricted to the host sandbox and to processes the registry recorded so a container cannot use it as an isolation escape. Change display and reset tools show differences and discard changes with timeout handling.

Search tools walk the workspace without descending into ignored directories, honour ignore matchers for directories and files, filter symbolic links pointing outside the workspace, skip oversized and non-text files, and return matching lines or file names with limits on results, scanned files, and line length, noting when ceilings are reached. Negated ignore patterns are ignored by design. An alternate shell path serves sandboxes without a direct file view, quoting the query literally and disabling option parsing.

The extraction tool renders one structured file to bounded plain text: markup to visible text with non-visible elements dropped, structured data pretty-printed, indented markup, tabular rows joined, markdown normalized to prose, and ini-like configuration reduced to settings. An optional main-content mode drops navigation, footer, sidebar, and form text through a skip-depth counter in the shared markup reader, leaving article text intact. Decoding tries a byte-order-mark-aware pass, then a UTF-8 pass, then a never-failing single-byte fallback. Files above the byte cap are refused with a pointer to windowed reads, unrenderable extensions are reported as notes, malformed structured content falls back to a short raw snippet, and the shell fallback supports only literal paths with safe quoting.

The web search tool is opt-in and has no endpoint by default. It queries the configured address with a text query and a bounded result count, sends a credential from the named environment variable when one is present, and expects a generic response shape containing a list of results with addresses, titles, and short snippets. Every returned address is screened by the same private-host and scheme checks used by the retrieval tool, displayed addresses have user information and credential-shaped parameters removed, and both the result count and total text are capped. The transport, decoding, size ceilings, and error-string contract are shared with the other web tools rather than reimplemented.

The tree-query tool matches literal paths and patterns against the walk with the same ignore, link, and ceiling rules, and adds a small brace-shaped syntax for listing children, one-level matching, recursive matching, and descending through literal directory segments, with the resolved target re-validated against the workspace root at every step. Shell metacharacters are rejected at the pattern level.

Web retrieval fetches an address, enforces scheme and size and decompression limits during and after inflation, decodes according to the declared character set with fallbacks, extracts visible text from markup while dropping non-visible elements and collapsing whitespace, screens private, loopback, link-local, reserved, and metadata hosts including alternative numeric encodings, resolves the host once at connect time and refuses private or unresolvable addresses, validates each redirect target including rejecting non-http schemes, pins the connection to the validated address, and returns an error string rather than raising. Credentials in an address are stripped from the displayed form and credential-named query parameters are redacted.

## Evaluators and Loggers

One evaluator runs a shell command and interprets a zero exit status without timeout as a pass, with per-task override support and tail truncation. Its configured timeout is validated into the allowed range at construction so an out-of-range value surfaces as a configuration error. A non-string task-level command is rejected as a failed evaluation instead of raising inside execution. The evidence tail is redacted for known secret formats before it is returned. The other evaluator always reports a neutral result for interactive sessions without automated grading.

The structured logger appends one serialized record per line with a timestamp, event name, and payload, using in-process and inter-process locks with verified stale handling: holder liveness is probed before a lock is broken, and any lock past a hard age ceiling is removed regardless so a wedged writer cannot block later records. It suppresses input and output errors, rotates the log aside at a bounded size, and counts records skipped under contention or lost to a failed write rather than losing them silently. It performs no redaction of its own; callers are responsible for the payloads they pass.

## External Tool Interoperability

Both directions use newline-delimited structured messages with no third-party dependency. The exposing side presents the same tool objects and workspace sandbox the loop uses, gates every invocation through the approval policy so a remote caller cannot reach what the local path would refuse, and reports a tool failure as an error-flagged result rather than a protocol fault. The consuming side launches each configured server as a child process, performs the handshake, lists advertised tools, and wraps each as an ordinary local tool whose name is folded into characters a function name may contain. The adapter ignores the local sandbox because work happens in the server's own environment, and registers as an external tool so the approval policy always requires explicit confirmation. A server that cannot start is reported and skipped so one broken optional server does not prevent startup.

## Terminal Primitives and Theme

Shared terminal helpers provide visible string width that counts wide characters double and zero-width characters as none, with joiner-sequence awareness scoped to each measured string; console size detection with a standard-library fallback; raw and input modes where one mode keeps interrupt signals delivered; safe writing that degrades unencodable characters without duplicating the written prefix; and UTF-8 output forcing with virtual-terminal enablement on the host console. Escape-sequence stripping treats an unterminated operating-system command as extending to the end of the string so it cannot corrupt width math, and recognizes colon-form colour sequences. The theme defines one restrained palette of styled tokens used by every surface the console draws, with one identity accent, distinct tokens for semantic states, and diff text colours aliased to the semantic tones so a future split changes one place.
