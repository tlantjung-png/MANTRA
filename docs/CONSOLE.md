# Console

## Terminal Interface

The console module provides the interactive terminal interface using only standard-library facilities. It implements styling via terminal escape sequences, with a flag to disable styling for non-terminal output, and ensures that escape-sequence processing is enabled on the host console where needed. The console forces UTF-8 output so box-drawing and wide characters render on narrow codepages.

The console is a single application-owned terminal surface. Every frame is composed into a full cell grid of character plus style per cell, diffed against the previously shown grid, and only the changed cells are written out. A dedicated reader thread translates raw terminal input into data events: keys, mouse, bracketed paste, and resize. One presenter loop drains that queue fully before drawing, batches streaming model output, throttles frames, and arms an animation tick only while something is actually animating, such as the spinner or drag auto-scroll. Because nothing is ever painted at a stale absolute position by a background thread, a resize is simply a full reflow and interleaved output can never tear a frame. The screen is an alternate screen with a top information bar showing workspace, model, approval mode, and cache rate; a scrollable transcript viewport; a border row carrying the spinner and status text; and the prompt box at the bottom. Text selection is drawn by the application: dragging over the transcript selects, releasing copies, with the system clipboard as the first route and an escape-sequence fallback for remote sessions. The wheel and page keys scroll. During a turn the operator can keep typing, and the next prompt is queued and sent when the turn ends. The busy check, the queue write, and the turn-end handoff are serialized through the application lock, so a prompt submitted exactly as a turn ends is either queued or started, never lost. Slash-command menus, endpoint and model pickers, secret entry, and approval prompts are overlay cards rendered into the frame. The prompt box is closed with corners and a right wall so long input never escapes it; its caret advances in display columns, so a wide character before the caret shifts it by two cells, matching what is on screen. A scroll marker rides the border row while the viewport is scrolled up. The layout wraps long lines at word boundaries, counting wide characters double, and re-emits open style codes when a wrap lands inside a colored word. Resize events re-wrap stored content and keep the same logical line at the top of the viewport.

On the byte-stream platforms the input decoder is explicit about every byte: a lone escape acts as the escape key rather than being typed into the prompt, the delete byte edits the buffer like backspace, control-one-byte ranges are dropped instead of inserted as text, alt-chords arrive as modifier-carrying keys, arrow-key modifier parameters decode into key modifiers so shifted and control-arrow bindings work, and a multi-byte character split across two reads is reassembled before decoding. Bracketed pastes are bounded in memory and delivered whole, with an unterminated paste cut off at the cap rather than buffered without limit, so no marker text can leak into the prompt and no paste can fill the queue unboundedly. The startup card is a centered adaptive block displaying the product name, tagline, and version. It is removed from the viewport buffer on the first turn rather than being painted over, and a resize while it is visible re-renders it centered for the new size instead of leaving truncated fragments of the old padding.

## Session Model

The console session owns the workspace, sandbox, context manager, system prompt, tools, client, approvals, and event bus. It maintains totals for tokens, turns, tool errors, and cache hits, per-turn cache metrics, and the most recent failure for the fix command. The sandbox is the host directory sandbox over the persistent workspace, and an empty repository is initialized if the workspace lacks one.

The session manages a streaming renderer that buffers fragments until line boundaries to apply formatting while tracking code-fence state, with sanitization of terminal escape sequences from model output. A spinner runs while the model is working and yields to real output. The viewport throttles rapid fragments to avoid flicker and forces a flush at stream completion so the final fragment is never delayed. A live approximate token counter is updated on a throttle.

While a task streams, a turn-scoped reader keeps native mouse selection working on the host and buffers non-scroll keys for the next prompt. Fragments received while a native selection is in progress are deferred and flushed once the drag ends. Tool observations render as budgeted boxes measured in viewport rows whose overflow is queued for an empty-Enter pager that pages through a screenful at a time; the pager queue can be persisted with the session so an interrupted paging session resumes where it left off. Structured unified diffs render as stacked old/new panes rather than a plus/minus line stream. File edits show a before/after diff against a snapshot taken when the tool call arrived, and brand-new writes show a syntax preview.

## Line Editor

The line editor reads single keys and provides completion for commands and workspace paths, with handling for navigation keys, deletion, and history, and a popup that can be dismissed or re-invoked via a dedicated key. The popup supports filtering as the operator types, selection via arrow keys, a hint area, and a count hint when the terminal is too small to render. Multi-line input renders as an upward-growing paste box with a size chip. Bracketed paste is assembled with an idle timeout, and mouse drag or click on a transcript line copies the selected text to the clipboard with a status flash. When standard input or output is not a terminal, the editor falls back to plain line input.

The completion popup for slash commands and at-mentions is a window that follows the selection; the overflow row pages the list by whole windows, by mouse click, or by running the selection past the edge. The mouse is captured only while the popup is open, so the terminal's native text selection keeps working the rest of the time. Dismissing the popup with the escape key lasts until the text changes, so a stray escape can never silence suggestions for the rest of the prompt, and the popup also works inside the multi-line paste box. While a turn is running, the escape key interrupts it exactly like a single interrupt keypress.

## File References

At-sign mentions are expanded by resolving tokens relative to the workspace, rejecting escapes via resolved path checks, and expanding globs with caps on hits and entries. Each file is capped, the total attached content is capped, and unknown references are reported. Directory listings for globs are limited, and content is truncated with a marker when caps are exceeded.

## Commands

Commands are invoked with a leading slash. The full set is listed by the help command: endpoint connection and credential replacement, model selection with an effort choice, workspace and memory inspection, difference display and change discard, approval-mode selection, cost and cache display, conversation summarization, clearing and resetting, conversation export to a Markdown or JSON file, session resume, goal and todo management, workflow creation and launching, skill discovery and attachment, external tool server inspection with runtime enable and disable that persists to the configuration file, the verbosity toggle, the suggestions toggle, and exit. The console banner displays model, endpoint, workspace, version-control status, approval mode, tool count, and instruction-file information.

After every agent reply the console shows a dim line of numbered next steps at the tail of the conversation. The line is derived from what the turn actually did: a failure leads with a diagnosis step, an edited file earns a step that names the file, and a verified change earns a commit step that counts the changed files. The subject of the prompt reserves a slot, so the line always points back at what was asked, and the subjects of recent turns are remembered, so switching to a new subject offers a step back to the previous thread. A number key or a click runs the step. The suggestions command turns the line off and on.

## Goals, Todos, Skills, and Workflows

The session supports goal injection where a standing objective and optional notes are rebuilt into the effective system prompt on every turn, with a cap that is re-applied after per-turn additions and with a check that notices when the agent reports the goal as complete. A session todo checklist is injected the same way, and agent-emitted completion lines are applied live during streaming and de-duplicated at turn end.

Skill attachment appends procedure text to the prompt for the current turn, with automatic routing that can attach a matching skill without being asked, subject to confidence and margin thresholds and to flags that disable automatic attachment or bundle launching. Auto-attached skills are detached when their turn ends. Bundles launch as ordered steps, attaching each skill in turn and restoring the previous attachment afterward. Workflows store named sequences of prompts and launch as ordered steps through the same session handler.

Auto-compaction summarizes the conversation via the language model client when the token threshold is exceeded, replacing the body with a summary while preserving the system prompt.

## Persistence

The session autosaves after each turn once the conversation is substantial, so a closing window can be resumed from the transcript list. Session save and load enforce size caps on file and payload, and path validation checks the resolved absolute form against allowed directories for both absolute and relative inputs, compared case-insensitively on platforms where path case does not distinguish files.
